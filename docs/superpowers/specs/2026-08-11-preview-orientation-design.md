# プレビュー枠の縦横対応 設計

作成日: 2026-08-11
関連: 別ウィンドウ分離は別spec（今回スコープ外）

## 背景と目的

現状プレビューは画面下部に全幅（横長）で置かれ、`Viewbox Stretch="Uniform"` で縦横比を保ったまま枠に収める。横向きアプリのスクショは問題ないが、**縦向きアプリのスクショは横長枠の中で細く小さくなり見えにくい**。

プレビュー枠を「横モード（現状）」と「縦モード（片側に縦長配置）」で切り替えられるようにし、縦画像を大きく見せる。手動切替に加え、縦横比の自動切替（誘導/強制/OFF）も設ける。すべて設定に保存。

## スコープ

**今回（この spec）:**
- A. プレビューの縦/横 手動切替ボタン
- B. 縦モード時のプレビュー配置（左右選択）
- C. 縦横比による自動切替（Off / Prompt / Force）

**今回スコープ外（別 spec）:**
- プレビュー枠の別ウィンドウ分離（切り出すと本体からプレビューが消え別窓へ）。実装が別物（ウィンドウ間のプレビュー移譲・状態同期）のため分離。

## 現状の把握（調査結果）

- レイアウトは単一カラムの縦積み（`MainWindow.xaml` ルート Grid）: 更新バナー(Auto) → ウィンドウ指定(Auto) → カット設定(Auto) → **プレビュー(`*` 可変)** → ログ(Auto)。
- プレビューは `Viewbox Stretch="Uniform"` 内の `ImgPreview`（`MainWindow.xaml:200-207`）。縦横比は保たれるが横長枠に縛られる。
- プレビュー画像はビットマップソースなので**画像の縦横（寸法）は取得可能**。自動切替は技術的に実現できる。
- プレビュー更新の契機は複数: ウィンドウ切替(`CmbWindows_SelectionChanged` → `CaptureTempPreview`)、キャプチャ(`ExecuteCapture`)、更新ボタン(`BtnRefreshPreview_Click`)。

## レイアウト2態

### 横モード（既定・現状のまま）
```
┌──────────────────────────────┐
│ ウィンドウ指定 [▼] [名前変更]  │
│ カット設定      [___]          │
│ ┌ プレビュー ──────[縦⇄横]─┐ │
│ │       [横長画像]          │ │
│ └──────────────────────────┘ │
│ ログ: ...              [展開]  │
└──────────────────────────────┘
```

### 縦モード（プレビューを片側に縦長・操作群は反対側に縦積み）
```
┌───────────────────────────────────────┐
│ ウィンドウ指定 [▼] [名前変更] ┌───────┐ │
│ カット設定      [___]         │ [縦⇄横]│ │
│                              │プレビュー│ │
│                              │(縦長)  │ │
│ ログ: ...          [展開]     │ [画像] │ │
│                              └───────┘ │
└───────────────────────────────────────┘
```
左右は詳細設定で入替可（既定＝右。左設定ならプレビューが左・操作群が右）。

## 機能詳細

### A. 手動切替ボタン
- プレビューカードの見出し行（`プレビュー` タイトルの右）に **[縦⇄横] トグルボタン**を1つ追加。
- 押下で `PreviewOrientation` を反転 → レイアウト組み替え → 該当モードの保存窓サイズへ自動リサイズ → 設定保存。

### B. 縦モードの配置と左右
- 縦モードではルート Grid を2カラム化し、片側=操作群（ウィンドウ指定/カット/ログ）、片側=プレビュー（縦長）に再配置。
- `VerticalPreviewSide`（Right/Left、既定 Right）で左右を決める。詳細設定(SettingsWindow)で変更・保存。
- **幅の振る舞い（2026-08-11 実機検証で変更）:** 操作群カラムは横モードの窓幅と同じ内容幅を固定で維持し、プレビューを可変幅（`*`）で「横に追加」する。窓幅＝操作群幅＋プレビュー幅。
  - 当初計画は操作群を固定360pxに縮める案だったが、キャプチャボタン文言（「スクリーンショットを撮る」）が見切れたため破棄。操作群は狭めない。

### C. 自動切替
- `PreviewAutoSwitch`: **Off / Prompt / Force**（既定 **Prompt**）。詳細設定で選択・保存。
- **判定タイミングはウィンドウ切替時のみ**（キャプチャ・更新ボタンでは判定しない。連打時にダイアログが出るのを防ぐ）。
- ウィンドウ切替で対象のプレビュー画像を取得し、縦長(高さ>幅)か横長かを判定:
  - **Off**: 何もしない（手動のみ）。
  - **Prompt**: 現在のモードと画像の向きが不一致なら「縦向き（横向き）にしますか？」と誘導。**同一対象アプリでは一度応答したら再度出さない**（対象ごとに1回まで。抑制フラグを対象単位で持つ）。
  - **Force**: 画像の向きに合わせて自動でモード切替（確認なし）。

## 設定モデル（`AppSettings` に追加）

- `string PreviewOrientation` = "Horizontal"（"Horizontal" / "Vertical"）
- `string VerticalPreviewSide` = "Right"（"Right" / "Left"）
- `string PreviewAutoSwitch` = "Prompt"（"Off" / "Prompt" / "Force"）
- 窓サイズを横用・縦用で別々に保存: 例 `HorizontalWindowWidth/Height`, `VerticalWindowWidth/Height`（既存 `WindowLeft/Top` とは別に、モードごとのサイズを保持）。切替時に該当サイズへリサイズし、手動リサイズは現在モードのサイズとして保存。
- 既存 `WindowLeft/Top`（位置）は共有のまま（位置はモード非依存）。

## レイアウト実装方針（altタイプ）

状態は2つ（横/縦）だけなので、**2つのレイアウトを用意して表示切替**するのが単純で堅牢:
- 案1（推奨）: XAML に横用・縦用の2レイアウトコンテナを持ち、`PreviewOrientation` に応じて一方を `Visible`／他方を `Collapsed`。プレビュー画像・カット関連の共有要素は、切替時に表示中コンテナへ再ペアレントするか、両レイアウトから同じ論理ツリーを参照する形にする。
- 案2: コードビハインドでルート Grid の行/列定義を動的に組み替え、各カードの `Grid.Row/Column` を付け替える。DRY だが再配置ロジックが増える。
- どちらにするかは実装計画(writing-plans)で確定。共有要素（`ImgPreview`・カットオーバーレイ・ウォーターマーク）の重複を避けることを優先する。

## テスト方針

- 設定モデル（3プロパティ＋モード別窓サイズ）の既定・シリアライズ往復を単体テスト。
- 向き判定ロジック（縦長/横長判定、現モードとの不一致判定、対象ごと抑制）を純粋関数に分離して単体テスト（画像寸法と現モードを入力に取る）。
- レイアウト切替・自動リサイズ・詳細設定UI・誘導ダイアログは実機確認（verify）。

## スコープ外（YAGNI）

- 別ウィンドウ分離（別 spec）。
- 縦横以外の任意角度・自由配置。
- プレビューのズーム倍率記憶などの追加機能（現状のズーム挙動は踏襲）。
